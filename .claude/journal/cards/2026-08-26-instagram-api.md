**Факт.** Добыто живой работой с боевой установкой 25–26.08.2026: рабочим приложением,
рабочим токеном и живыми доставками, а не чтением документации. Значения (идентификаторы,
имена аккаунтов, домены) убраны — у вашей установки они свои.

## Флоу и хост

Поток — **Instagram Login** (не Facebook Login): хост `graph.instagram.com`, версия `v25.0`,
токен вида `IGAA…`. Facebook Page для этого не нужна; более того, `graph.facebook.com/me`
с этим токеном отвечает `401 Cannot parse access token` — это не поломка токена, это другой
хост. Тип аккаунта — professional (Business или Creator); личный аккаунт Direct через API
не отдаёт вообще.

## Два разных идентификатора приложения — главный капкан

| Что | Где живёт | Против чего работает |
|---|---|---|
| Meta App ID | карточка приложения, Settings → Basic | `debug_token` на `graph.facebook.com` принимает только его |
| Instagram App ID | Instagram → API setup with Instagram login | против него выдаётся токен `IGAA…` |

Meta заводит второе, Instagram-приложение сама, дописав к имени суффикс `-IG`. При путанице
ответ — «Error validating application. Cannot get application info due to a system error»,
причём ОДИНАКОВЫЙ и с верным, и с мусорным секретом (секрет тут не проверяется). Мусорный
App ID вместо этого даёт «Invalid Client ID» — так и различаются причины отказа.

## Что работает на Standard Access («Готово к тестированию»)

`/me`, `/me/media`, `/me/insights`, `/me/content_publishing_limit`, `/me/subscribed_apps`,
`POST /me/messages`. App Review для этого не нужен: Standard Access покрывает аккаунт
владельца приложения и аккаунты с ролью в приложении. Роль обязана быть ПРИНЯТА в самом
приложении Instagram — непринятое приглашение выглядит настроенным, но данных не даёт.

## HTTP 200 с пустым телом — это НЕ «данных нет»

`/me/conversations` отдаёт 0 бесед, включая только что созданную; `/{media}/comments` — 0
при `comments_count=70`; `/{igsid}?fields=name,username` — `{}` при существующем профиле.
Признак: пустой `data` при НЕПУСТЫХ курсорах `before`+`after` означает, что коллекция есть,
а элементы вырезаны фильтром доступа. Принять пустой ответ за отсутствие данных — самая
дорогая ошибка разбора этой платформы: чинить начинают не то.

## Публикация приложения обязательна и не равна App Review

Meta пишет прямо в секции вебхуков: «Для получения уведомлений Webhooks у приложения должен
быть статус "Опубликовано"». Без публикации события не приходят ВООБЩЕ и без единой ошибки —
токен живой, свои данные отдаются, подписка выглядит настроенной. Публикация — тумблер
в разделе «Опубликовать», бесплатно, мгновенно и обратимо; App Review — заявка со
скринкастом, для своего аккаунта не нужна. Публикацию блокируют два пустых поля в
Settings → Basic: privacy policy URL и категория приложения.

## Ограничения платформы

Писать первым нельзя. Входов ровно два: человек написал сам (окно 24 часа, тег `HUMAN_AGENT`
продлевает до 7 суток) и private reply на комментарий (окно 7 суток, **ровно одно** сообщение
на комментарий; продолжение — только если человек ответил). Conversations API отдаёт детали
лишь по 20 последним сообщениям треда, а запросы старше 30 дней не отдаёт вовсе. IGSID берут
ИЗ ВЕБХУКА, не из API: в payload комментария есть `from.username`, в payload директа —
только IGSID.

## Подписка

`POST /me/subscribed_apps?subscribed_fields=comments,messages`, проверка —
`GET /me/subscribed_apps` возвращает оба поля. Подписка без `comments` даёт установку, где
директ работает, а кодовые слова в комментариях не срабатывают.

**Почему важно.** Каждый пункт этой карты ловит установщика молча: сервис и дашборд выглядят
настроенными, ошибок нет, событий тоже.

**Как проверить.** `./scripts/doctor.sh` — он спрашивает у Meta ровно эти вещи и печатает,
чем каждая проверка может соврать. Факт публикации машиной не проверяется вовсе: единственный
честный признак — доходят ли события.

**Отдельно, о безопасности приёмника.** Подпись `X-Hub-Signature-256` — это ВОРОТА, а не
пометка: неподписанное событие не пишется в базу вовсе. Иначе любой желающий пишет в базу
установки с улицы и занимает ключ события подделкой, после чего настоящее событие считается
дубликатом. Реализация — `signature.py`, считает HMAC по СЫРЫМ байтам тела; пересериализованный
JSON даёт другую подпись, а пустой секрет закрывает роут, а не открывает.
