# Безопасность

## Куда сообщать об уязвимости

1. **Приватно:** вкладка **Security** репозитория → **Report a vulnerability**. Это
   предпочтительный путь: сообщение видно только автору, и до правки о дыре не узнают
   те, у кого пакет уже стоит.
2. Если приватная кнопка недоступна — заведите **issue** с описанием КЛАССА проблемы
   («обходится проверка подписи вебхука», «панель пускает без пароля при таком-то
   условии») без рабочего эксплойта, без токенов и без чужих данных в тексте, и напишите,
   что готовы прислать детали приватно.

Публичный эксплойт в issue бьёт не по автору, а по чужим установкам: у каждой из них
живой аккаунт Instagram и никого, кто следит за обновлениями.

## Честно об ожиданиях

**Поддержки у этого пакета нет** — ни по установке, ни по вопросам, ни по срокам.
Ответа на сообщение может не быть, сроков реакции не существует, вознаграждения тоже.

И всё же **сообщения об уязвимостях принимаются, а issues оставлены включёнными
намеренно**: единственный канал, по которому до автора вообще может дойти сообщение
о дыре, важнее видимости поддержки. Дырам, в отличие от вопросов по конфигурации,
здесь рады.

Обновления выходят только для последнего состояния ветки `main`. Бэкпортов в старые
коммиты и версионирования нет: обновление установки — это `./scripts/update.sh`.

## Что относится к пакету, а что к вашей установке

**Уязвимость пакета** (сообщайте):

- обход проверки подписи `X-Hub-Signature-256` — запись в базу установки с улицы;
- обход входа в панель установки или доступ к админ-роутам мимо прокси;
- инъекция в SQL, выполнение чужого кода, чтение файлов сервера;
- активный HTML или скрипт в панели через тексты правил, имена или данные события;
- утечка секретов в логи, в HTML-страницы или в сообщения об ошибках (токен доступа,
  App Secret, пароли, ключ конверта);
- выход из контейнера или повышение прав внутри него.

**Не уязвимость пакета** (чинится у вас, не здесь):

- ваша конфигурация: порт базы, открытый в интернет; слабый пароль панели; секреты,
  выложенные в чат или в публичный репозиторий вашего форка;
- поведение самой платформы Meta — это в программу Meta, не сюда;
- «в зависимости есть CVE» без демонстрации, что через него достаётся эта установка;
- отсутствие того, чего пакет намеренно не делает (см. README): рассылок, нескольких
  аккаунтов, обхода лимитов платформы.

## Если утёк секрет ВАШЕЙ установки

Это чинится вами и быстрее, чем любой ответ автора. Порядок по убыванию срочности:

1. **Токен доступа** — отзовите его в дашборде Meta и вставьте свежий в панель
   (`/panel` → «Токен»). Пока старый жив, им можно писать от имени вашего аккаунта.
2. **App Secret** — перевыпустите в Settings → Basic, впишите новое значение в файл
   окружения установки, затем `./scripts/update.sh`. До этого подпись вебхуков считается
   старым секретом, и события перестанут приниматься — это ожидаемо.
3. **Пароль панели** — в окружении лежит его хеш, а не сам пароль. Новый хеш считается
   тем же кодом, который потом его проверяет (второй реализации формата не заводить —
   разъехавшись, она закроет панель без видимой причины):

   ```bash
   printf '%s\n' 'новый-пароль' | docker run --rm -i "$(docker build -q .)" python panel.py
   ```

   Полученную строку впишите в `IG_ADMIN_PASSWORD_HASH` в файле окружения установки и
   выполните `./scripts/update.sh`. Пароль идёт по конвейеру, а не аргументом команды:
   `argv` виден в `ps aux` любому пользователю хоста.
4. **Ключ конверта `IG_TOKEN_KEY`** — им зашифрован токен в базе. Сменили ключ —
   сохранённый токен больше не расшифровывается; порядок восстановления («удалить строку
   токена → свежий токен в окружение → `update.sh`») описан в `docs/INSTALL.md`,
   раздел «Если токен протух между обновлениями».
5. **Пароль базы** — правка одного значения в окружении НЕ меняет пароль роли: роль
   создаётся один раз, при создании тома, и файл инициализации больше не читается
   никогда. Менять надо в самой базе (`ALTER ROLE`), и только потом в окружении.
   Иначе сервис уходит в рестарт-петлю, а прокси начинает отвечать 502 на всё —
   и выглядит это как поломка прокси.

Файл окружения установки не коммитьте никогда: он в `.gitignore`, и это не формальность —
в нём ключ, которым расшифровывается сохранённый токен доступа.

## Что уже сделано в пакете

Чтобы не сообщать о том, что закрыто:

- подпись вебхука — ворота, а не пометка: неподписанное событие не попадает в базу вовсе,
  пустой секрет закрывает роут, а не открывает;
- токен доступа лежит в базе зашифрованным (AES-256-GCM), а не открытым текстом;
- токены и секреты вычищаются из логов на уровне обработчика логирования, а не
  «мы стараемся их не печатать»;
- админ-роуты закрыты на уровне прокси и отвечают снаружи 403 с пустым телом;
  `doctor.sh` проверяет это отдельной строкой, потому что тихо разошедшийся конфиг прокси
  выглядит как рабочая установка;
- контейнер сервиса работает под непривилегированным пользователем, с ограничением
  памяти и числа одновременных запросов;
- тексты правил рисуются в HTML с автоэкранированием — их пишет человек, но публикует
  их страница.
